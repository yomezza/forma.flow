# Технические решения для демонстрационной модели 01

Источник: [идея](https://github.com/yomezza/forma.flow/blob/ideas/01-specialists/idea.md#L7-L70). Ни одно решение ниже не является изменением Go/PostgreSQL backend.

| ID | Решение в рамках DemoAPI | Почему |
|---|---|---|
| D-01 | Сохраняем `localStorage` key `formaTela.demo.v1`, увеличиваем поле `version` до 4 и делаем миграцию повторяемой | Не терять пользовательские демо-данные |
| D-02 | Начально один `room` и один `specialist`, у специалиста все активные услуги; исторические заявки не перепривязываем молча | Идея 01 говорит о текущем одном кабинете; избегаем выдуманной истории |
| D-03 | Публичная заявка стартует с `specialistId:null`, `roomId:null`, `clientId:null` | Исполнитель/кабинет выбираются внутри распределителя и администратором, клиент не выбирает специалиста, телефон не удостоверяет личность |
| D-04 | Автоматическое назначение кабинета **при сохранении администратором назначения**: выбрать первый совместимый свободный кабинет, не ставить ложные жёсткие roomId всем публичным заявкам | Не сокращать возможность размещения неназначенных заявок в многокабинетной схеме |
| D-05 | Доступность строится на **совместном поиске назначения всех активных заявок**; шаги времени привязаны к опубликованному студийному расписанию | По отдельности свободный массажист/кабинет недостаточен |
| D-06 | Если администратор явно ухудшил размещаемость другой неназначенной заявки, та помечается `indirect_assignment_conflict`; новые заявки не должны ухудшать защищённую выполнимую часть компонента | Разрешённое исключение не равняется праву на новые необеспеченные слоты |
| D-07 | Состав кабинетов/специалистов и старые заявки всегда сохраняются при архивации и утверждении отсутствия; нарушения становятся предупреждениями | Не терять историю |
| D-08 | Учебные логины и демонстрационная смена роли — только UI-симуляция; ни пароль, ни его хеш не сохраняются в localStorage | Не изображать надёжную авторизацию там, где её нет |
| D-09 | Роли в аккаунте могут совмещаться; выбор `activeRole` не меняет список прав и не одобряет собственное отсутствие автоматически | Следуем идее и отделяем организационный сценарий от механизма аутентификации |
| D-10 | Специалист может завершать **свой** подтверждённый сеанс только после планового окончания, и отменять своё завершение без срока | Соответствие [решениям о завершении](https://github.com/yomezza/forma.flow/blob/ideas/01-specialists/idea.md#L45-L50) |
| D-11 | Личный график специалиста — повторяющаяся неделя + исключения и утверждённые отсутствия. Расширенный персональный календарь не вводим | Соответствие [правилам графиков](https://github.com/yomezza/forma.flow/blob/ideas/01-specialists/idea.md#L28-L34) |
| D-12 | Демо алгоритм имеет бюджет поиска, при превышении возвращает `CAPACITY_CHECK_LIMIT` / неизвестность, **но никогда не принимает запись наугад** | Сложность NP-типа; корректнее отказать, чем ложно зарезервировать |
| D-13 | История завершений и переназначений — события. Специалист видит лишь собственные события переназначения без телефона и чужих текущих записей | [Ограничения приватности](https://github.com/yomezza/forma.flow/blob/ideas/01-specialists/idea.md#L36-L43) |
| D-14 | Событие `forma-change`, методы `Promise` и существующий `SiteAPI` остаются. Не загружать внешние фреймворки | Совместимость с текущим frontend |

## Открытые технические границы, не вопросы владельцу

- Начальный специалист создан как демонстрационный профиль «Специалист № 1», имя изменяемо администратором. Миграция не приписывает старые выполненные массажи этому человеку без подтверждения.
- Дата/время в демо продолжают использовать локальные `YYYY-MM-DD` и `HH:mm`. Для повторяемых тестов — подставной clock; зона кабинета из settings.timeZone при наличии. Если зона не задана, демо обозначает локальный режим как ограничение, не обещает production TZ-корректность.
- Одновременно можно утвердить отсутствие и оставить проблемное старое назначение; оно не становится допустимым новым назначением.
- Начало и конец интервала: `[start,end)`. Перерыв резервирует время после каждого сеанса до `end + breakMinutes`.
- `rooms` — независимые сущности в данных уже сегодня, даже если для клиента виден единственный кабинет.
- **Отложено владельцем:** SQL, Go-пакеты, миграции БД, production API/OpenAPI, серверная RBAC и безопасность.

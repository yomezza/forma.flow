# DemoAPI / SiteAPI

Документ описывает frontend-контракт `dist/js/demo-api.js`. Все методы асинхронные и возвращают Promise. UI обращается к данным только через `SiteAPI`, сейчас это псевдоним `DemoAPI`. Демонстрационное хранилище localStorage с ключом `formaTela.demo.v1` не синхронизируется между посетителями.

## Сущности

- **Service**: id, name, description, durationMinutes, priceAmount, currency, sortOrder, isActive, visualSymbol.
- **Booking**: id, serviceId, снимок name/durationMinutes/priceAmount/currency, date (`YYYY-MM-DD`), time (`HH:mm`), status, опциональные clientId/clientName/clientPhone, createdAt/updatedAt и поля переходов статуса.
- **Client**: id, fullName, phoneNormalized в формате `+7##########`, createdAt, updatedAt.
- **Schedule**: `settings` хранит простой недельный график, блокировки и vacations. `schedule.activeMode` выбирает `simple` или `advanced`. В расширенном режиме published и drafts — словари правил по дате, history — до 30 изменений.
- **Day rule**: kind `working | off | unplanned`, intervals — упорядоченные непересекающиеся пары start/end, stepOverride — число минут или null.
- **Vacation**: id, startDate, endDate. Даты включительны. Пересечение периодов запрещено.

## Слоты и заявки

| Метод | Назначение |
|---|---|
| getAvailableSlots(date, serviceId) | Вычисляет свободные начала с учётом активного режима, длительности, рабочих интервалов, шага, перерыва, блокировок, отпуска, текущего времени и занятых записей. |
| createBooking(data) | Совместимый метод демо-записи без данных клиента, создаёт confirmed. Перед записью повторно проверяет слот. |
| createBookingRequest(data) | Основной путь сайта. Проверяет слот повторно, нормализует телефон, находит/создаёт клиента и создаёт pending_confirmation с фиксированным снимком услуги и контактов. Проверка и сохранение выполняются одним изменением базы. |
| getBookings() | Возвращает все записи. |
| getPendingBookings() | Возвращает заявки, ожидающие подтверждения. |
| updateBooking(id, {status}) | Совместимый переход статуса. |
| confirmBooking(id) | Подтверждает ожидающую заявку и сохраняет confirmedAt. |
| cancelBooking(id, note?) | Отменяет pending или confirmed, сохраняет время и примечание. |
| completeBooking(id) | Завершает только confirmed. |
| restoreBooking(id) | Восстанавливает отменённую запись после повторной проверки слота. |
| deleteBooking(id) | Удаляет запись из демо-истории. |
| getBookingsForDate(date) | Возвращает записи за дату. |
| getBookingWarnings() | Возвращает ID активных заявок, которые не помещаются в текущий опубликованный график. Статусы не меняются. |

Статусы: `pending_confirmation → confirmed → completed`. pending_confirmation и confirmed можно отменить. Отменённые записи не занимают время. Ожидающие подтверждения резервируют слот так же, как подтверждённые.

## Расписание и история

| Метод | Назначение |
|---|---|
| getScheduleMode() | Возвращает активный режим. |
| previewScheduleModeChange(mode, start, end) | Считает изменившуюся доступность и активные записи вне нового графика за обозримый диапазон. |
| setScheduleMode(mode) | Активирует simple или advanced и пишет событие в историю. |
| getPublishedSchedule(start, end) | Возвращает опубликованные правила диапазона. |
| getDraftSchedule(start, end) | Возвращает черновые правила диапазона. |
| getDateSchedule(date) | Возвращает active, draft, published для даты. |
| getDateStates(start, end, serviceId?) | Возвращает состояние дат для клиентского календаря: рабочая, выходной, отпуск, блокировка, не опубликовано, нет свободных слотов или прошедшая дата. |
| setDraftSchedule(date, rule) | Создаёт/заменяет черновик даты. |
| setDraftScheduleRange(start, end, rule) | Создаёт черновики на диапазон. `{week: {...}}` задаёт правила по дням недели. |
| copySimpleScheduleToDraft(start, end) | Копирует текущую простую недельную модель в независимые дневные черновики. |
| previewSchedulePublication(start, end) | Возвращает число и виды изменяемых дней, а также активные записи вне расписания. |
| publishScheduleRange(start, end) | Публикует и удаляет только черновики внутри диапазона. `unplanned` снимает публикацию. |
| unpublishDate(date) | Создаёт черновик снятия публикации для одной даты. |
| getScheduleHistory() | Возвращает последние действия расписания с before/after. |
| previewRestore(versionId) | Показывает последствия восстановления прежнего состояния. |
| restoreScheduleVersion(versionId) | Восстанавливает предыдущую версию в черновик. Автоматической публикации нет. |
| getBookingWarnings() | Вычисляет отметки «Вне графика» из активного расписания. |

Simple использует workDays, start, end, step, breakMinutes, blockedDates, vacations. Vacation действует только в simple. Advanced принимает только опубликованные дневные правила. Черновики посетителям не видны. Рабочая сессия должна целиком помещаться в один интервал, а интервал между сеансами соблюдается при проверке занятости.

## Отпуска

| Метод | Назначение |
|---|---|
| getVacations() | Возвращает периоды отсутствия. |
| createVacation(data, confirmedIds?) | Создаёт отпуск; при активных бронированиях возвращает VACATION_CONFLICT с counts/ids и ждёт повторного вызова с явным подтверждением конфликтующих ID. |
| updateVacation(id, data, confirmedIds?) | Аналогично меняет существующий период. |
| deleteVacation(id) | Удаляет период, после чего слоты пересчитываются. |
| isVacationDate(date) | Проверяет попадание даты в отпуск. |

Отпуск блокирует новые записи, имеет приоритет над простым выходным, но существующие бронирования сохраняются. Записи получают вычисляемую отметку, а статус не меняется.

## Настройки, содержимое и перенос данных

| Метод | Назначение |
|---|---|
| getSettings(), updateSettings(patch), resetSettings() | Читает, изменяет или сбрасывает параметры расписания и оформления. |
| getContent(), updateContent(patch) | Читает и меняет тексты публичного сайта. |
| exportData() | Возвращает всю базу, включая расписание, историю и clients. |
| importData(data) | Проверяет и заменяет базу. Поддерживает миграцию прежних версий. |
| resetDemoData() | Сбрасывает демо-данные. |

Ошибки имеют code, например VALIDATION, NOT_FOUND, SLOT_UNAVAILABLE, VACATION_CONFLICT. Изменения отправляют событие `forma-change`. Web Locks используются для сериализации записей между вкладками, где поддерживаются.

## Требования к будущему backend

Сохранить асинхронный контракт и смысл ответов. Операцию «проверить слот + создать/найти клиента + создать заявку + зафиксировать снимок услуги» сделать транзакционной и защищённой от дублей/пересечений. Публикацию диапазона, переключение режима, обновление отпуска и историю изменений тоже выполнять атомарно. Авторизовать административные методы на сервере. Время кабинета, часовой пояс и конфликт между предпросмотром и публикацией должны обрабатываться сервером.
